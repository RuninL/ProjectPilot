# ProjectPilot 产品规格（1.1.0）

> 版本：1.1.0 ｜ 正式支持平台：Windows 10/11 x64 ｜界面语言：简体中文 ｜日期格式：YYYY-MM-DD ｜时区：Asia/Hong_Kong

## 1. 产品定位

本地个人使用的桌面项目管理软件，面向个人的工程、科研、课程设计和 FSAE 项目管理。核心闭环：

**项目 → 任务 → 甘特图 → Milestone → 会议记录 → 行动项 → 任务 → Dashboard 风险追踪**

完全离线可用，所有数据存本机 SQLite。

## 2. 范围

### 2.1 范围内（第一版）

1. 项目管理：创建/编辑/查看/归档/恢复/永久删除；概览含进度、风险、近期会议与 milestone
2. 任务管理：六态（todo/in_progress/blocked/postponed/done/cancelled）、四级优先级、两层父子、筛选/搜索/排序/批量修改、预估/实际工时
3. Dashboard：严格只读地展示今日/未来 7 天到期、逾期、未来 30 天 milestone、项目完成率、近期会议及未完成行动项、四类派生风险
4. 结构化风险：项目归属、分类、可能性、影响、自动等级、状态机、负责人、缓解计划和截止日期；支持集中筛选与项目内维护
5. 会议与行动项：会议可关联项目或独立存在；行动项一键转任务（双向关联、不可重复转换）
6. Milestone：四态（upcoming/achieved/missed/cancelled）、倒计时/逾期显示、可选关联任务（完成仅提示，不自动改状态）
7. Gantt：跨项目并行总图 + 逐项目周/月/季度时间轴、任务时间条、状态图例、FS 依赖、循环/跨项目/排期冲突检测
8. Calendar：月视图（任务起止/截止、会议、milestone），点击跳详情
9. 人物与参与人：人物 CRUD 和二级详情；项目/任务参与关系独立；列表支持参与人多选 OR 筛选
10. Files & Links：项目内与全局 `/files`；仅存 URL 或本地路径；安全打开与复制；无效路径提示
11. Import/Export/Backup：全量 JSON 导入导出、项目/任务/里程碑/风险 CSV 导出、SQLite 备份/恢复
12. Settings：主题（深/浅/暖橙/彩色/跟随系统）、数据路径说明与打开、示例数据管理、备份/恢复/导入/导出、关于

### 2.2 范围外（明确不做）

- 账号、登录、权限、多人协作、云同步、服务器、API Key、付费服务
- 文件内容上传/托管（只存路径与 URL）
- Gantt 拖拽调整、日历拖拽排程（后续版本考虑）
- 语音转写；AI 自动修改数据（未来 AI 仅为用户确认后写入的建议层）
- Firebase / Supabase / MongoDB / PostgreSQL / 一切云数据库
- 移动端、macOS/Linux 打包（架构不排斥，但第一版不验证）

## 3. 页面信息架构

路由采用 hash 路由（`createHashRouter`），避免 Tauri 自定义协议下的深链问题。
下表为**实际路由栈**；标注「后续阶段」的能力在界面上以不可点击的占位卡片呈现，绝不伪造功能。

```
应用外壳 AppLayout（左侧主导航 + 内容区）
├── / ····························· Dashboard
├── /people ······················· 人物列表
│   └── /people/:id ··············· 人物详情（项目 → 任务）
├── /projects ····················· 项目列表（活动/已归档/全部 + 搜索/状态/排序）
│   └── /projects/:projectId ······ 项目详情：概览统计 + 任务/里程碑/会议/风险区（同页，不再拆二级路由）
├── /tasks ························ 任务：跨项目任务列表（筛选/搜索/排序/批量修改）
│   └── /tasks/:taskId ············ 任务详情
├── /gantt ························ 并行总图 + 逐项目甘特图
├── /calendar ····················· 月视图日历（任务截止 + 会议 + 里程碑，只读）
├── /meetings ····················· 全部会议（跨项目 + 独立会议）
│   └── /meetings/:meetingId ······ 会议详情：纪要/决议/风险 + 行动项 CRUD + 转任务
├── /risks ························ 风险登记册（创建/编辑/删除 + 项目/状态/等级/分类/搜索筛选）
├── /files ························ 全局文件与链接
└── /settings ····················· 设置（主题 + 清除示例数据；其余为后续阶段）
```

- 左侧主导航（10 项）：仪表盘、人物、项目、任务、甘特图、日历、会议、风险、文件、设置
- **项目详情不设二级路由**：任务区与项目概览同页呈现，切换任务筛选不改变 URL。
  甘特图与任务依赖管理自阶段 3 起同页呈现；里程碑区（`#project-milestones`）与
  会议与行动项区（`#project-meetings`）、风险区（`#project-risks`）与文件和链接区
  （`#project-links`）同页呈现；仅关键路径与拖拽排期仍以「后续阶段」占位卡片列出。
- 会议详情是唯一的行动项写入入口：项目详情的会议区只列出该项目的会议并链接到详情页。
- `/tasks`（任务）与项目详情的任务区共用同一套实现（`TaskWorkspace`）：
  前者跨项目并显示项目筛选，后者锁定单一项目。
- 所有列表页必须有：空状态（含引导创建）、加载状态、数据库错误状态（可重试）

## 4. 用户核心流程

### 流程 A：项目启动与排期

1. 创建项目（名称、颜色、开始/目标结束日期）
2. 创建 milestone（关键节点）
3. 创建任务（可两层分解），设置起止日期与 FS 依赖
4. 在甘特图检查时间轴，系统标出循环依赖/排期冲突，修正日期

### 流程 B：日常跟进

1. 打开 Dashboard，查看今日/未来 7 天到期、逾期、会议、milestone 与风险卡
2. 进入任务更新状态/进度/实际工时（done 自动进度 100）
3. blocked 任务与其影响的后续任务在风险区可见

### 流程 C：会议决议闭环

1. 记录会议（主题、日期、参会人、议程、讨论、决定、风险）
2. 添加行动项（内容、负责人、截止日、状态）
3. 一键将行动项转为任务 → 建立双向关联；已转换的行动项按钮变为"查看任务"，不可重复转换
4. 任务进入项目排期与 Dashboard 追踪，形成闭环

### 流程 D：数据安全

1. 设置页一键备份 SQLite
2. 恢复前系统自动备份当前库并二次确认
3. 全量 JSON 导出用于迁移；单项目 CSV 导出用于汇报

## 5. 功能细则与判定规则

### 5.1 任务规则

- v1.1 **未引入项目/任务状态机**；所有项目状态和任务状态可自由切换，`postponed` 可从任意状态进入并切回任意状态
- `done` 时自动置 progress=100 并写入 `completed_at`；从 done 撤回时**清除 `completed_at` 但保留 progress=100**，任务仍可继续编辑
- `cancelled` 不计入项目完成率（分母分子都剔除）；`postponed` 不计完成但保留在分母；
  `archived_at` 非空的任务同样不计入
- 项目完成率 = done 任务数 / 非 cancelled 任务数（无任务时显示"暂无任务"而非 0%）
- 父任务最多两层：父任务本身有父任务时，不允许再作为其他任务的父任务（DB 触发器 + service 双重校验）
- 父任务不得自引用、不得跨项目；已有子任务的任务不能再成为子任务（UI 直接禁用该选项）
- **归档项目下禁止新建任务**：UI 隐藏入口并给出原因，service 层再次拦截
- **删除仍有子任务的任务被拒绝**：确认框显示真实子任务数量，要求先处理子任务；DB 的 CASCADE 仅作兜底
- 批量修改支持：状态、优先级、截止日期（含清空）；执行前列出将执行的修改并二次确认，
  提交经 Rust `execute_batch` 单事务完成，任一条失败整批回滚
- 任务归档字段 `archived_at` 已进入 schema 与查询/完成率口径，**本阶段不提供归档/恢复任务的界面**

### 5.2 Dashboard（严格只读）与派生风险规则（四类）

| 风险                 | 判定                                                                                                             |
| -------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 逾期未完成           | `due_date < today` 且 status ∉ {done, cancelled, postponed}                                                      |
| 临期低进度           | `today ≤ due_date ≤ today+7天` 且 progress < 50 且 status ∉ {done, cancelled, postponed}                         |
| 受阻传导             | 从 status=blocked 的任务出发，沿 FS 依赖正向可达的所有未完成后续任务                                             |
| Milestone 前置未完成 | `today ≤ milestone.date ≤ today+14天`、milestone 非 achieved/cancelled，且其关联任务的前置依赖链上存在未完成任务 |

- 任务区域分别列出 `due_date = today`、`today < due_date ≤ today+7天` 与 `due_date < today` 的未完成任务；
  done、cancelled、postponed 与 archived 任务不进入任何区域或派生风险。
- 近期会议为 `today ≤ date ≤ today+7天`，每场会议同时列出其未完成行动项；行动项不提供写入入口。
- milestone 分为当天、逾期和未来 30 天（`today < date ≤ today+30天`）三组，均排除 achieved/cancelled。
- 所有派生风险都由一次有界 repository 读取后在内存计算，不写入数据库；卡片仅导航到对应任务或 milestone。
- "今日/未来 7 天/逾期"一律以 Asia/Hong_Kong 本地日历日判定（详见 architecture.md §日期策略）。

### 5.2a 结构化风险登记

- 风险字段：项目、标题、描述、分类（范围/进度/资源/技术/外部/其他）、可能性、影响、状态、负责人、
  缓解计划、截止日期；可能性 × 影响实时显示并持久化为 low/medium/high/critical 等级。
- `/risks` 和项目详情 `#project-risks` 均可创建和编辑；编辑时项目不可迁移。
  `/risks` 支持项目、状态、等级、分类筛选和标题/描述搜索，默认排序为开放、监控、已缓解、已关闭，
  再按风险等级、截止日期、更新时间。
- 合法状态迁移仅为 `open → monitoring/closed`、`monitoring → mitigated/closed`、
  `mitigated → open`、`closed → open`。表单只给出当前状态和合法目标，service 在 `updateRisk`
  与 `setStatus` 两条路径再次拒绝越级变更；进入 mitigated/closed 写入 `resolved_at`，重开则清空。

### 5.3 会议与行动项规则

- 会议可关联项目，也可独立存在（`project_id` 为 NULL，列表中标注「独立会议」）
- 会议 `start_time` 为可选的 `HH:MM` 本地墙钟文本（无时区），格式与 0–23 时范围由 DB 触发器与 Zod 双重校验
- 参与者以 JSON 数组存库；表单按换行或中文逗号拆分，回填时一行一人
- 删除会议的二次确认框显示**真实行动项数量**，并明示已转换出的任务会保留
- 仅未转换（converted_at 为空）的行动项可转换
- 转换经 Rust `execute_batch` 单事务完成：条件插入任务 + 条件回写 converted_task_id；
  受影响行数不等于 2 即整体回滚（详见 database-schema.md §2.6 四层防御）
- 任务默认值：标题=行动项内容、描述=负责人 + 行动项内容、截止日=行动项截止日、
  项目=会议关联项目（独立会议则弹窗要求用户选择目标项目，未选择时确认按钮禁用）、状态=todo
- 转换进行中按钮显示「转换中…」并禁用，防止重复提交
- 已转换行动项显示「查看任务」链接；关联任务被删除后行动项显示「任务已删除」，且**不重新开放转换**（防重复语义以 converted_at 历史为准，删除任务时保留审计字段）

### 5.4 Milestone 规则

- 倒计时 = milestone 日期与今日（Asia/Hong_Kong 日历日）的差：未来显示「剩余 N 天」，
  当天显示「今天到期」，已过且非 achieved 显示「已逾期 N 天」
- 关联任务全部 done 时，弹出提示询问是否将 milestone 置为 achieved——**绝不自动更改**；
  选择「否，保持当前状态」不产生任何写入，状态与 `achieved_at` 保持原值
- 置为 achieved 时写入 `achieved_at`；missed 由用户手动设置或在提示中确认，系统只提示不代改
- 归档项目下禁止新建/编辑/删除里程碑：UI 禁用入口并给出原因，service 层再次拦截
- 删除里程碑的二次确认框明示关联任务不会被删除

### 5.4a Calendar 规则（月视图）

- 六周固定网格、周一为首日；月份切换基于 `YYYY-MM` 字符串运算，跨年正确
- 同一天可同时出现任务截止、会议与里程碑：以中文文字标签 `[任务截止]`/`[会议]`/`[里程碑]`
  区分类型，**不以颜色作为唯一信号**
- 单日条目过多时折叠为「还有 N 项」，点击展开、可「收起」
- 点击条目跳转：会议 → `/meetings/:id`、里程碑 → `/projects/:id#project-milestones`、
  任务 → `/tasks?taskId=:id`
- 仅当当前月份包含今日时标出「今天」标记
- **只读视图**：不提供拖动或改期能力，界面明确说明

### 5.5 Gantt 规则（第一版）

- 范围：单项目，入口在项目详情页内；自研纯 SVG，不引入 Gantt 库
- 视图：周/月/季度三档时间轴 + 今日线；时间轴可横向滚动，任务名称列固定不随滚动隐藏
- 元素：任务时间条（按状态着色）、任务名称、FS 依赖箭头、状态图例
- 颜色不作为唯一信号：图例以中文列出每个状态，任务条的可访问名称同时包含状态、起止日期、
  冲突与受阻风险说明
- milestone 菱形**尚未实现**：阶段 4 的里程碑能力落在项目详情的里程碑区与日历月视图，
  甘特图内的菱形不在阶段 4 执行清单内，仍推迟到后续阶段，界面上不伪造菱形
- 无 start_date 的任务不绘制，但在图下方按名称列出中文提示；有 start_date 无 due_date 按**单日条**渲染并附文字说明
- 检测：循环依赖（加边前阻止写入，提示涉及的任务名称）、排期冲突（两端日期齐全且
  前驱 due_date > 后继 start_date 才成立，日期为空不产生伪冲突）、跨项目依赖（UI 不允许创建，
  DB 触发器兜底；对导入产生的存量数据以警示标记）
- 受阻风险为派生提示：由依赖图从 blocked 前驱正向传导计算，不写入 tasks.status；前驱恢复后自动消失
- 本阶段不做拖拽、不自动排程、不在 Gantt 内直接写库；日期修改经任务编辑表单，保存后 Gantt 即时刷新
- `/gantt` 顶部并行总图让所有项目共享时间轴，每项目一行；支持状态筛选、隐藏已完成/已推迟及今日线。
  缺日期时依次使用任务日期范围、已有单侧日期，最终以今天单日兜底，并在行内明确说明。

### 5.6 Files & Links 规则

- 类型：`url`（浏览器打开）与 `file_path`（系统默认程序打开）
- 打开本地路径前检查存在性，不存在弹提示且提供"复制路径"
- URL 仅允许 http/https 协议打开，其余只允许复制（防协议注入）
- 每条记录保存资料名称、目标地址/路径、可选备注与审计时间；项目删除时随外键级联删除
- 软件只保存 URL 或本机路径字符串，不上传、复制、读取、托管或嵌入文件内容
- 本地路径必须是 Windows 绝对路径；文件移动或删除后快捷方式失效，但原路径仍可复制
- UI 按钮与 service 双重执行协议白名单；本地路径由最小 Rust command 检查存在后交给官方 opener
- `/files` 聚合全部项目资料，按名称/描述搜索并按项目/类型筛选，CRUD 仍复用相同 service 与安全规则

### 5.6a 人物与参与人规则

- `/people` 支持姓名/邮箱/角色搜索和 CRUD；详情以项目为一级、该项目下任务为二级，可多项目同时展开，
  并以文字标记「项目参与 / 仅任务参与 / 两者兼有」及「未归属项目」。
- 任务参与人与项目参与人相互独立，分配任务不会自动加入项目参与人；任务候选来自全部人员。
- 非项目成员可正常保存任务，只显示提示和显式「加入项目参与人」按钮；未点击绝不写项目关系。
- 移除项目参与人只提示受影响任务数，不移除任务分配；移除任务参与人也不影响项目关系。
- 项目与任务列表的参与人筛选均为对象多选 OR，且分别只读取 `project_participants` /
  `task_participants`；表单参与人状态与筛选状态分离。

### 5.7 导入/导出/备份规则

- JSON 导出：当前 12 张应用表（含 people 及两类独立参与关系）+ `schemaVersion=1` +
  导出时间 + 应用版本 + 分实体统计；保留 ID、外键、时间戳与 `is_sample`
- JSON 导入：先严格校验 schema 版本、每行 Zod 结构、统计、外键、两层任务、转换唯一性与依赖环 →
  预览统计 → 显式选择合并/替换 → 二次确认 → 单事务写入（失败整体回滚）；
  合并模式对人员采用同 ID/同名跳过，两类关系分别校验和恢复，绝不相互推导
- CSV 导出：项目、任务、milestone、风险；项目/任务含各自参与人列，可选单项目或全部项目，UTF-8 with BOM、中文表头与中文枚举；
  CSV 为单向导出，不提供 CSV 导入；以公式字符开头的文本会加单引号，避免 Excel 公式注入
- 备份：保存对话框选择路径，文件名含时间戳；Rust 使用 SQLite online backup，正确包含 WAL 中已提交数据
- 恢复：校验 SQLite 完整性与必要表 → 自动生成带时间戳的当前库安全副本 → 二次确认 →
  SQLite online backup 覆盖；完成后提示重启应用

### 5.8 示例数据规则

- 首次启动询问是否载入"示例项目"（含任务/依赖/milestone/会议/行动项各若干）
- 所有示例行 `is_sample=1`，UI 中以"示例"徽标区分
- 设置页一键"清除示例数据"（单事务删除全部 is_sample=1 行）
- JSON 导出默认排除示例项目及其关联数据，可勾选“包含示例数据”；勾选后保留全部
  `is_sample` 标记，以保证备份/迁移可无损往返

## 6. 非功能要求

- 冷启动 ≤ 3s（普通硬盘 Windows 10）；常规查询响应 ≤ 100ms（千级任务量）
- TypeScript strict、禁止 any；所有表单 Zod 校验；危险操作二次确认
- 空/加载/错误/无效输入四态全覆盖；数据库错误以用户可读文案呈现并可重试
- 单机单实例运行（Tauri single-instance），避免双开写库冲突
